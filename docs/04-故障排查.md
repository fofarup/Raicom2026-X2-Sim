# 常见故障排查

## `git lfs pull` 后仍是很小的文本文件

检查：

```bash
ls -lh vendor/link_u_os_competition-main.tar.gz
head vendor/link_u_os_competition-main.tar.gz
```

正常文件约 511 MB。若开头出现 `version https://git-lfs.github.com/spec/v1`，说明
LFS 对象没有下载：

```bash
git lfs install
git lfs pull
```

## `docker info` 权限不足

```bash
sudo usermod -aG docker "$USER"
```

然后**注销 Ubuntu 账户并重新登录**。仅仅新开终端通常不够。

## Docker 拉取镜像超时 / 极慢

中国大陆访问 Docker Hub 受限。推荐方案：

### 方案 A：配置 HTTP 代理（推荐）

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo tee /etc/systemd/system/docker.service.d/http-proxy.conf >/dev/null <<EOF
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:7897/"
Environment="HTTPS_PROXY=http://127.0.0.1:7897/"
Environment="NO_PROXY=localhost,127.0.0.1"
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

> 注意：代理和镜像加速器（`registry-mirrors`）同时使用时可能冲突，建议只配代理。

### 方案 B：配置镜像加速器

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<EOF
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF
sudo systemctl restart docker
```

## MuJoCo 窗口没有出现 / 空白

检查：

```bash
echo "$XDG_SESSION_TYPE"
echo "$DISPLAY"
xhost
```

第一项应为 `x11`，`DISPLAY` 通常类似 `:0` 或 `:1`。修复：

```bash
xhost +local:docker
# 或允许所有连接：
xhost +
```

然后重启容器：

```bash
cd ~/x2_ws/x2_biao
bash scripts/stop_all.sh
bash scripts/start_container.sh
```

## MuJoCo 窗口非常卡 / 帧率极低

**这是最常遇到的问题。** 检查 OpenGL 渲染器：

```bash
docker exec raicom2026-x2-sim glxinfo | grep "OpenGL renderer"
```

| 输出 | 含义 | 操作 |
|------|------|------|
| `NVIDIA GeForce RTX ...` | GPU 硬件渲染 ✅ | 正常 |
| `llvmpipe` | CPU 软渲染 ❌ | 需要配置 GPU |

若显示 `llvmpipe`，说明 GPU 未直通到容器：

1. 确认宿主机有 NVIDIA 驱动：`nvidia-smi`
2. 安装 nvidia-container-toolkit
3. 确保容器启动带 `--gpus all`
4. 检查 `config/project.env` 中 `USE_NVIDIA_GPU=1`

## 仿真启动后崩溃

查看崩溃日志：

```bash
docker exec raicom2026-x2-sim \
  ls /workspace/.runtime/raicom2026/sim_mujoco/bin/log/crash/
docker exec raicom2026-x2-sim \
  cat /workspace/.runtime/raicom2026/sim_mujoco/bin/log/crash/*.crash
```

### 常见崩溃：`AimRTException: Get executor [MujocoSimModule/hds] failed`

**原因**：HDS 组件需要额外的执行器配置，当前配置中不存在。

**解决**：`scripts/in_container/start_sim.sh` 中已内置环境变量：

```bash
export AGIBOT_ENABLE_HDS_COMPONENT=0
export AGIBOT_ENABLE_EVENT_COMPONENT=0
export AGIBOT_ENABLE_AUDIT_COMPONENT=0
```

手动启动时若遇到此错误，请使用 `scripts/in_container/start_sim.sh`，不要直接调用 `aima-sim-app`。

### 常见崩溃：X11 相关（`libxcb-xfixes.so` 等）

**原因**：容器无法连接 X Server。

**解决**：见上方 "MuJoCo 窗口没有出现"。

## 找不到 `libgrid_map_msgs__rosidl_typesupport_cpp.so`

不要在宿主机手工复制动态库。先确认使用本项目构建的镜像和运行环境：

```bash
docker exec raicom2026-x2-sim \
  bash -lc 'source /opt/ros/humble/setup.bash; ros2 pkg prefix grid_map_msgs'
```

然后重新构建 AimDK 消息：

```bash
docker exec -it raicom2026-x2-sim \
  bash -lc '/workspace/scripts/in_container/build_aimdk.sh'
```

## Python 报 `No module named aimdk_msgs`

检查构建产物：

```bash
ls .runtime/ros/install/aimdk_msgs
```

进入容器后检查：

```bash
source /workspace/scripts/in_container/common.sh
python3 -c 'import aimdk_msgs; print(aimdk_msgs.__path__)'
```

## `Service not available`

通常表示 MC 尚未启动、启动失败，或通信域不同：

```bash
./scripts/status.sh
docker exec raicom2026-x2-sim printenv ROS_DOMAIN_ID
```

输出必须为 `26`。MuJoCo、MC 和控制脚本都应由本仓库脚本启动。

## ROS 2 setup.bash 报 `unbound variable`

常见于以 `set -euo pipefail` 运行的脚本中。本项目的 `scripts/lib/common.sh` 和
`scripts/in_container/common.sh` 已处理此问题。

如需自行编写脚本，避免使用 `set -u`，或在使用前设置：

```bash
set +u  # 关闭 nounset
source /opt/ros/humble/setup.bash
```

## 机器人不动

依次确认：

1. MuJoCo 与 MC 均在运行；
2. 已执行 `set_mode.py JD` 和 `set_mode.py SD`；
3. 已在 MuJoCo 窗口点击 **Reset**；
4. 已执行 `set_mode.py LD`；
5. 再运行 `safe_forward.py`。

任何顺序不确定时，先停止：

```bash
bash scripts/stop_all.sh
```

## 容器被 OOM 杀掉（Exited 137）

**原因**：MuJoCo 仿真 + CPU 软渲染内存占用极高（可达 8GB+）。

**解决**：
- 使用 GPU 加速可大幅降低内存占用（仿真降至 ~2.4GB）
- 或增加系统内存 / swap
