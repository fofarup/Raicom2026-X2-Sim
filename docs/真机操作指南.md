## 一、X2 机器人硬件架构

### 1.1 三块计算单元

X2 内部有三块计算板，各司其职：

| 单元 | 名称 | IP | 职责 | 是否能部署代码 |
|------|------|----|------|:---:|
| PC1 | 运控计算单元 | `10.0.1.40` | 运动控制（行走、站立、手臂） | ❌ **禁止** |
| PC2 | 开发计算单元 | `10.0.1.41` | 二次开发（你的代码） | ✅ **放这里** |
| PC3 | 交互计算单元 | — | 语音、屏幕、表情 | ❌ |

**PC2 硬件规格**（你的代码跑在这里）：
- 芯片：NVIDIA Jetson Orin NX
- 算力：157 TOPS
- 内存：16 GB
- 存储：512 GB
- GPU：1024 核 Ampere + 32 Tensor Cores
- CPU：8 核 Arm Cortex-A78AE

### 1.2 通信架构

```
你的笔记本 (10.0.1.2)
    │  网线直连
    ▼
PC2 开发板 (10.0.1.41)
    │  ROS 2 跨板通信 (ROS_DOMAIN_ID=26)
    ├── PC1 运控 (10.0.1.40)
    │     └── 接收速度/手臂命令 → 控制电机
    └── PC3 交互
          └── 屏幕/表情/语音
```

**关键**：ROS 2 话题跨板共享。你在 PC2 发 `/aima/mc/locomotion/velocity`，PC1 直接收到并执行。

### 2.1 有线直连（比赛唯一推荐方式）

1. 网线一头插笔记本，另一头插机器人背部的 **"二次开发网口"**（不要插运控网口）

```bash
ping 10.0.1.41

```

## 四、真机导航实现

### 4.1 导航方式对比

| 方式 | 原理 | 得分 | 实现难度 |
|------|------|:---:|:---:|
| **方式 A**：组委会建图 | 工作人员用 APP 建好地图 → 存到 PC2 → 你读地图+定位数据导航 | 15+8 分 | ⭐⭐ |
| **方式 B**：自主建图 | 笔记本/PC2 控制机器人自己建图 → 自己定位 → 自己导航 | 15+8+50 附加 | ⭐⭐⭐⭐⭐ |

**建议**：省赛和国赛都用方式 A（组委会建图）。附加分 50 分需展示完整自主激光建图流程，难度极高。

### 4.2 方式 A：基于组委会建图导航（推荐）

#### Step 1：组委会建图

比赛前，工作人员用官方 APP 遥控机器人走一遍场地，APP 自动建图并保存到 PC2：

```
/agibot/data/var/MapManagerModule/<map_id>/
├── grid_map.png          # 地图图片
├── grid_map_info.txt     # 分辨率、原点、尺寸
└── ...
```

#### Step 2：获取地图

```python
# 你的代码中获取地图数据
from aimdk_msgs.srv import GetStoredMapByName
import rclpy

node = rclpy.create_node("get_map")
client = node.create_client(GetStoredMapByName, "/aimdk_5Fmsgs/srv/GetStoredMapByName")

req = GetStoredMapByName.Request()
req.map_name = "raicom_2026"  # 组委会告知的地图名

future = client.call_async(req)
rclpy.spin_until_future_complete(node, future)
map_data = future.result()
# map_data.map_info.resolution  # 分辨率
# map_data.map_info.width       # 宽度
# map_data.data                 # 栅格数据 (-1=未知, 0=空闲, 100=占据)
```

也可以用 `map_tf_distribution` 包（我们项目里已经有了）读取地图和定位：

```bash
ros2 launch map_tf_distribution map_tf_bringup.launch.py \
  map_yaml:=/agibot/data/var/MapManagerModule/<map_id>/grid_map.yaml
```

#### Step 3：定位（重定位）

比赛开始前，需要告诉机器人它在哪：

```python
import std_msgs.msg as std_msg

# 1. 触发重定位
pub = node.create_publisher(std_msg.String, "/integrated_command", 10)
pub.publish(std_msg.String(data="start_relocalization:raicom_2026"))

# 2. 等 1 秒，发布初始位置估计
time.sleep(1.0)
from geometry_msgs.msg import Pose
pose_pub = node.create_publisher(Pose, "/relocalization_pose", 10)
init_pose = Pose()
init_pose.position.x = -1.5   # 出发区坐标（地图像素坐标）
init_pose.position.y = -1.5
init_pose.orientation.w = 1.0
pose_pub.publish(init_pose)

# 3. 订阅激光定位结果
# 收到 /slam/lidar_odom 数据 = 重定位成功
```

**坐标转换**：`/relocalization_pose` 用的是**像素坐标**。从 `grid_map_info.txt` 读转换参数：
```
第1行: 分辨率 (20 像素/米)
第2行: 地图原点像素坐标 (可用作初始位姿)
第3行: 图像尺寸
```

#### Step 4：导航

重定位成功后，通过 `/slam/lidar_odom` 获取实时位置，用 `move_toward()` 导航到目标点。**这和仿真里用里程计导航完全一样**——只是数据源换成了 `/slam/lidar_odom`。

```python
# navigator.py 源码里真机模式就是用这个：
node.create_subscription(
    PoseStamped,
    "/map_tf_distribution/localization_pose",  # 从 TF 读取的位姿
    self._on_pose_stamped,
    10,
)
```

**比赛流程中 SLAM 的主要命令**：

| 操作 | 话题/命令 | 说明 |
|------|----------|------|
| 建图 | 发 `start_mapping` 到 `/integrated_command` | 仅方式 B 需要 |
| 停止建图 | 发 `stop_mapping:<地图名>` | 仅方式 B 需要 |
| 重定位 | 发 `start_relocalization:<地图ID>` + 初始位姿 | 比赛中每次启动都要做 |
| 获取实时位姿 | 订阅 `/slam/lidar_odom` 或读 TF `map→base_link` | 导航循环使用 |

### 4.3 和仿真的区别

| 项目 | 仿真 | 真机 |
|------|------|------|
| 位置来源 | `/aima/hal/odom/state` | `/slam/lidar_odom` 或 TF |
| 地图 | 不需要（直接用坐标） | 需要先重定位 |
| 避障 | 无（仿真里激光空数据） | 有（真实激光雷达） |
| 速度 | 0.3-0.5 m/s | 日常 ≤0.8 m/s, 最大 1.8 m/s |

### 4.4 导航代码切换

我们的 `navigator.py` 已经处理了真机/仿真切换：

```python
if sim:
    # 仿真：订阅里程计
    node.create_subscription(Odometry, "/aima/hal/odom/state", self._on_odom, ...)
else:
    # 真机：订阅 TF 定位
    node.create_subscription(PoseStamped, "/map_tf_distribution/localization_pose", ...)
```

真机上跑时**不加 `--sim`** 即可自动切换。

## 五、真机比赛操作流程

### 5.1 赛前准备（场地适应）

```
1. 网线连接笔记本 ↔ 机器人"二次开发网口"
2. 笔记本设 IP: 10.0.1.2/24
3. SSH 登录: ssh agi@10.0.1.41
4. 确认 ROS 2 通信正常
5. scp 代码到 PC2: ~/raicom2026/
6. 确认组委会建好地图，获取 map_name/map_id
7. 测试重定位是否成功
```

### 5.2 比赛 20 分钟流程

```
裁判下令开始
    │
    ▼
① 启动 competition_node.py（不加 --sim）
    │
    ▼
② 机器人自动执行 SD → Reset → LD
    │
    ▼
③ 任务1：队员语音"前往交互区I"
    → 机器人重定位 → 自主导航到交互区-I → 正面朝向交互区-II
    │
    ▼
④ 任务2：队员交互
    → 时间问答 → 数字颜色识别 → 表情 → 动作
    │
    ▼
⑤ 任务3：队员表达需求
    → 语音应答 → 自主导航到作业区 → 抓取 → 语音播报
    │
    ▼
⑥ 完成（如时间允许，可进行第二次运行）
```

### 5.3 安全注意事项

- **机器人摔倒立即停止**——代码有骨盆高度检测（<0.45m 判定跌倒）
- 碰撞围挡裁判有权终止运行
- 不得触碰机器人（除规则允许的交互队员）
- 严禁使用机器人自带语音大模型——必须用自己的离线 ASR

## 八、常见问题

### Q: ROS 2 通信不上？
```bash
# 检查 ROS_DOMAIN_ID
echo $ROS_DOMAIN_ID  # 应该是 26
# 检查话题
ros2 topic list | grep aima
```

### Q: 重定位失败？
- 确保地图名/ID 正确
- 确保初始位姿在地图范围内
- 等待 `/slam/lidar_odom` 有数据输出

### Q: 机器人不走路？
- 确认已注册 MC 输入源
- 确认模式是 `LOCOMOTION_DEFAULT`
- 第一条速度指令超过启动门限（forward_velocity > 0.09）

### Q: 手臂不动作？
- 确认已切换到 `UPPERBODY_REMOTE_SPLIT` (US) 模式
- 确认 `/mc/upper_body_command` 话题有发布者
